# AnnZarro HPC benchmarks

Server-side latency, payload and memory of AnnZarro at atlas scale, run on the Fred Hutch
HPC cluster (Slurm, `<partition>`, HPC compute nodes: Intel Xeon Gold 6254). Results and
interpretation: [FINDINGS.md](FINDINGS.md). Tidy data: `results/`.

## What is measured

Every case is one AnnZarro API request for one vector: a gene column, a cell row, an obsp or
varp row, an obsm column, an obs column, or the cell-name list. The protocol is
(`scripts/bench_http.py`):

- **cold**, 5 repeats: the touched arrays are evicted from the node page cache with
  `posix_fadvise(DONTNEED)` (verified with `mincore`; `resident_before` / `resident_after_evict`
  columns), then a **fresh** gunicorn server process is started and the request is made once.
  Repeat 0 is the only true first touch (`first_touch=1`); the NFS filer's own cache is not
  controllable from a client.
- **warm**, 5 per cold repeat (25): the same request again in the same process.
- **newidx**, 1 per cold repeat: an untouched index in the same, now-warm process ("next click").

Latency is client-side time to the last byte over 127.0.0.1. The server peak RSS is VmHWM of
the single gunicorn worker read from `/proc` after each request. Indices are seeded
(`seed=20261001`, per case `crc32(seed_key)`) and are paired across layouts and filesystems.
`scripts/bench_raw.py` runs the exact zarr slicing call AnnZarro issues (`array[[i]]` /
`array[:, [j]]`) with the same indices and protocol, without Flask, JSON or HTTP.

## Software

- AnnZarro: settylab/annzarro `main` @ `63b57e6658531777d7354ba50b6b9c9f82b83b6a`, installed
  non-editable (a snapshot, not a moving tree).
- Python 3.11.14. Every other package is pinned in `requirements.lock.txt`
  (`uv pip compile requirements.in`); zarr 3.1.6, numcodecs 0.16.5 and numpy 2.4.6 match the
  live instance.
- The server config mirrors the live pilot (`scripts/wsgi_bench.py`): auth off, cache on,
  8000 MB / 6 datasets. Gunicorn runs with 1 sync worker (3 for the concurrency test).

## Reproduce

```bash
B=$SCRATCH/annzarro-bench            # any scratch root
uv venv --python 3.11 $B/venv
VIRTUAL_ENV=$B/venv uv pip sync benchmark/hpc/requirements.lock.txt
git clone https://github.com/settylab/annzarro $B/src/annzarro
git -C $B/src/annzarro checkout 63b57e6658531777d7354ba50b6b9c9f82b83b6a
VIRTUAL_ENV=$B/venv uv pip install --no-deps $B/src/annzarro
# inputs
sbatch slurm/rechunk.sbatch                          # spatial-A chunk sweep stores
sbatch slurm/build_pairwise.sbatch                   # kernels / distances / correlations
sbatch slurm/rechunk_atlas.sbatch 1024,1024          # and all,4 4096,64 8192,128 16384,64 ...
# measurements (one spec per experiment; specs are generated by scripts/make_specs.py)
python scripts/make_specs.py chunksweep $B/specs/chunksweep.json --fs hpctemp
sbatch --export=ALL,SPEC=$B/specs/chunksweep.json,OUT=$B/runs/chunksweep/http.csv slurm/run_http.sbatch
sbatch --export=ALL,SPEC=$B/specs/chunksweep.json,OUT=$B/runs/chunksweep/raw.csv  slurm/run_raw.sbatch
sbatch slurm/fsarm.sbatch ; sbatch slurm/concurrency.sbatch
python scripts/collect.py $B/runs benchmark/hpc/results
```

The scripts hard-code the paths used for the paper runs (`$SCRATCH/...` and the served
liver data under `$DATA_ROOT/...`); change `BENCH` / `LIVER` in `scripts/make_specs.py` and `B`
in `slurm/*.sbatch` to rerun elsewhere. Every spec that was run, and every job's captured
environment (node, CPU, RAM, mounts, package versions, annzarro commit, bench commit and
dirty state), is in `results/environment.json`.
