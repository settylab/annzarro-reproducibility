`overview.png` was re-shot on the same install (`--only overview`) after the volcano tile's title changed to US
spelling ("Kompot volcano, color = ..."): only the title strip differs from the previous capture (x 1873-2542,
y 257-287 capture px); the four `overview_*_tile.png` files and `overview_status.json` came out byte-identical.

The PyPI wheel ships `static/vendor`; a fresh git checkout does not until
`scripts/vendor_assets.py` has run, and without it the page does not render, so check one
capture before trusting a run from a checkout.

Deep links use the fragment form `/?dataset_path=<abs path>#view=<base64url JSON>` and are
built from `data_prep/demo_panelsets/*.view.json`, so they follow the local dataset path.
A capture is taken only when no request is in flight, no loading screen, overlay or spinner
is visible, every Plotly graph has drawn its traces, and that state has held for 1.5 s.
Toasts and hover labels are hidden at capture time; there were no toasts in the final run.
Each run writes its log (console errors, table counts, click results) to `screens/.screenshots.log`.

`*_tile.png` files crop one tile's content area: the plot or table without the app header,
tile title bar or Plotly mode bar.

Choices made for these figures:
- The overview and focus walk UMAPs use reversed **Blues**, not view A's reversed Hot.
  With Hot a zero-probability cell is white on white, so the UMAP outline disappears
  (see `A_kernel_walk.png`). With Blues it is light grey.
- Frame 4 is the protocol's example monocyte `Mature_Young_2#TCAATTCAGTGAGGCT-1`. At
  95d0e64 it was drawn under a neighbour, so a click there focused
  `Mature_Old_2#TATTTCGAGATTGAGT-1` and the script fell back to
  `Mature_Young_1#CAACCAAGTATACCCA-1`. Since 0.3.1 the first click lands. The script still
  tries candidates near the monocyte median until the focused cell is the one clicked,
  and logs each attempt.
- Fig. 2 sets four focus tiles in one row and the E table beside its UMAP, so those views
  use narrower or shorter windows than the default: UI text, axis labels and status lines
  then keep a legible size at print width.
- **Fetch claims in the Fig. 2 caption are checked by the script.** `--only filtercheck`
  (also part of a full run) opens view E with only its first condition (319 HSCs), applies
  the full two-condition filter through the table's SearchBuilder, and fails the run unless
  the masked UMAP drops to 290 "In table" cells with **zero** `/api/v1/data/` requests from
  that moment until the page settles. As a control, the same listener sees the view's own
  loading requests. v0.4.1 also polls `/api/v1/data/fingerprint` (the store's identity, no cell
  data) in the background after a store opens; the checks log those polls and leave them out of
  the counts. The focus sequence fails the run unless
  each click makes exactly one `/api/v1/data/obsp/diffusion_walk_t5?rows=<i>` request
  ("each click fetched one row"). **This set (78c9da6):** 12 `/api/v1/data/` requests
  while view E loads; In table 319 -> 290 with **0** data requests after the filter (one
  fingerprint poll); clicks 2-4 one `diffusion_walk_t5` row request each, click 2 also
  one fingerprint poll.
- **Status-line inset (Fig. 2a).** The overview run also writes `overview_status.json`:
  the CSS-px rectangle of each plot's status line and of its text. `fig5_app.py` crops the
  fold-change UMAP's line ("8,090 cells") from `overview.png` itself and sets it as a
  framed callout in the left margin at 6 pt in print (×2.9 panel a's scale), joined to a
  box on the source. No status line in Fig. 2's views carries a reason: all are
  `plot-status--ok`, since nothing is hidden. The bottom-left plot is used because its
  line borders the free margin, so the leader crosses no data. Without the JSON (captures
  made before this), the figure is drawn without the inset.
- **Known print limitation:** in the printed Fig. 2 (183 mm, set at text width) the
  per-plot status lines ("8,090 cells", "16,285 genes") come out at about 2.5 pt, the same
  as the app's other UI text and tick labels. They are legible on screen and when zoomed,
  not on paper; the inset above shows one at 6 pt.
- The share field is scrolled to its start (`scrollLeft = 0`) so the host and
  `dataset_path` are visible. The selection is unchanged.

## UI bugs and glitches seen (not fixed)

Items 1 to 10 were seen at 95d0e64. On 0.3.1 the run log has no console errors, page
errors or toasts, so 3 and 4 are gone; 5 is gone (the "Not in table" legend sits above the
plot, and "In table" is shown by the colour bar); 8 is gone (table and plot tiles show the
same chevron). 1 was not re-checked; the script keeps its workaround. 2 changed: the panel
area keeps a fixed height and a "Create New Panel" chooser fills the page below it, so
the overview fixes the panel height and hides the chooser. 6 still holds. 11 is new.

1. **Deep-link `controlState: false` is ignored and breaks small tiles.** Steps: open
   view C (or any layout whose tile is half height) at 1600×1000. Every tile shows its
   full control panel. The graph area of a half-height tile collapses to about 0 px and
   Plotly throws `Something went wrong with axis scaling` (`Error loading plot data`). The
   tile then stays blank, or shows "Some data could not be read: plot data: failed to
   read". Cause: `updateDatasetLoadingState` (`panels/plot-utilities/panel-ui-make.js`,
   `$controlsContainer.toggle(isDatasetLoaded)`) and `cell-table.js:64` show the controls
   after the dataset loads, overriding what `restoreLayout` applied. Workaround in the
   script: a stylesheet holds the controls closed while the view loads, then each tile's
   own toggle button collapses them.
2. **Page height grows with content.** `body` has `min-height: 100vh` and no fixed
   height, so a tall tile (a table with its SearchBuilder) pushes the 2×2 layout below the
   fold, and the page scrolls. The script grows the window to the document height
   (overview 1263 px, E 1106 px).
3. **`pageerror: Cannot set property searchBuilderConfig of #<Object> which has only a
   getter`.** Thrown on every load of a deep-linked cell table that has a
   `searchBuilderConfig` (overview, view E), from `cell-table.js:187`
   (`_settings.searchBuilderConfig = sb_data` after `delete` on a non-configurable
   getter) when the table refreshes. The filter still applies.
4. **Spurious console errors on every page load:** "DataTables.SearchBuilder not loaded
   properly", "buttons/searchBuilder extension not available". The check in `index.html`
   looks for `$.fn.DataTable.buttons` and `.searchBuilder` (lower case), but SearchBuilder
   does work.
5. **View E legend overlap:** the "Not in table" legend entry is drawn on top of the
   colour-bar title (`E_umap_tile.png`, right edge).
6. **SearchBuilder takes most of a table tile.** It cannot be collapsed. In the overview
   it leaves about 4 rows visible, and the 5th row is clipped mid-line above the info and
   paging bar.
7. **Tiny categorical legend markers.** The legend symbols on the cell-type UMAP (views D
   and focus) are drawn at point size 3, so the colours are hard to match to labels.
8. **Inconsistent toggle chevron.** After collapsing, a table tile shows an up chevron
   while plot tiles show a down chevron (overview, view E).
9. **Share Link field is narrow** (about 190 px) and, because the whole link is
   selected, it shows the link's tail by default. The header grows by one row when the
   field opens.
10. **Single-tile layouts leave the lower part of the tile empty:** a lone cell-plot
    tile at 1600×900 draws the graph in about the top 60 % of the tile. The focus
    sequence therefore uses two tiles side by side.
11. **SearchBuilder overlaps the table's own controls when the tile is narrow** (0.3.1).
    At 720 px (view E's saved 45 % of 1600) the row count "Showing 1 to 25 of 290
    entries (filtered from 8,090 total entries)" runs under the pager and is cut; below
    about 1,000 px the SearchBuilder box covers the first letter of the "Search:" label.
    View E is therefore shot with the table at 65 %.
