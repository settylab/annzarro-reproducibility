### What it is

Two programs from the Chan Zuckerberg Initiative share the name, and the matrix row mixes them. **Explorer** is the hosted viewer behind CZ CELLxGENE Discover: a Python (Flask) server that reads datasets converted to TileDB `.cxg` arrays on S3, plus a React/WebGL client. **Annotate** (`pip install cellxgene`) is the older open-source program Explorer was forked from: a Python server that loads your own h5ad and serves the same style of client, with user annotation editing. Every cell below says which of the two it rests on. When only one of them has a feature, the row mark follows the stronger one; the evidence column names which.

**Primary paper.** Megill C, Martin B, Weaver C, Bell S, Prins L, Badajoz S, et al. (2021). cellxgene: a performant, scalable exploration platform for high dimensional sparse matrices. *bioRxiv* preprint 2021.04.05.438318. [doi:10.1101/2021.04.05.438318](https://doi.org/10.1101/2021.04.05.438318). Crossref-verified 2026-10-03 (title, posted 2021-04-06, 22 authors, preprint on bioRxiv). Abstract (bioRxiv API, v1): "differentiated by its ability to performantly handle millions of observations".

**Later paper.** CZI Cell Science Program, Abdulla S, Aevermann B, Assis P, Badajoz S, Bell SM, et al. (2025). CZ CELLxGENE Discover: a single-cell data platform for scalable exploration, analysis and modeling of aggregated data. *Nucleic Acids Research* 53(D1):D886-D900. [doi:10.1093/nar/gkae1142](https://doi.org/10.1093/nar/gkae1142). Crossref-verified 2026-10-03 (title, journal, volume 53, issue D1, pages D886-D900, online 2024-11-28, print 2025-01-06, 54 authors with the consortium first). Full text: [PMC11701654](https://www.ncbi.nlm.nih.gov/pmc/articles/PMC11701654/). Relevant sentence: "Explorer ... allows researchers to dynamically explore, compute and query individual datasets for up to 4.3 million cells in <1 min".

**Disagreements with current marks**
- shareable view state: P -> N. Neither a link nor a file restores the view; only the dataset (Explorer URL) or the labels (Annotate CSV) come back. If the author counts annotation CSVs as "state", keep P, but then state it in COMPARISON_NOTES.
- hosted multi-user: P -> Y. Discover's Explorer is a single deployment serving all users; Annotate documents multi-user self-hosting. "Only curated datasets" belongs under remote stores.
- Reported scale: "≥1M cells" -> "4.3M cells (NAR 2025); 11.4M served on Discover". Documented and observed figures for a single dataset, both Explorer.

### Scale check: the 11.4M-cell dataset in the hosted Explorer

I checked this on 2026-10-04 with three runs in headless Chromium, using the same method as the UCSC check ([`demos/scale_probe/probe_web.py`](demos/scale_probe/probe_web.py); see ucsc-cell-browser.md). The question was whether Explorer really draws a dataset above the 4.3M cells that the data portal's contributor docs give as the visualisation limit. manuscript-writer cites `single-cell-data-portal` `frontend/doc-site/032__Contribute and Publish Data.mdx` L31: datasets with more than 4.3 million cells "can be submitted but will not visualized in CELLxGENE Explorer".

**Dataset.** Qiu et al. 2024, a single-cell transcriptional timelapse of mouse embryonic development, "Whole dataset: Raw counts only", 11,441,407 cells: [Explorer link](https://cellxgene.cziscience.com/e/dcfd4feb-18a3-4b30-81d7-1b0c544a8ab3.cxg/).

|---|---|---|---|---|---|---|---|
| 08:11:38 | 11,441,407 | 17.1 s | 0.32 s | 846 MB | 1.55 GB | 0.61 GB | 95.8 MB |

**Findings**
- **Explorer draws every cell of an 11.4M-cell dataset.** All 11,441,407 points go out in one draw call, and the UI reads "11441407 of 11441407 cells" ([s01](screens/cellxgene/s01_scale_all_cells_drawn.jpg)). So the 4.3M figure is a limit on what the portal visualises, or a stale one, not a limit of Explorer's renderer. The data portal still offers this dataset in Explorer.
- **Not aggregated.** The UMAP request is `layout/obs?layout-name=umap&nbins=5000`. `nbins` quantises the coordinates onto a 5,000-step grid for transfer: 64.7 MB, about 5.9 bytes per cell. It does not bin cells together, as the point count shows.
- **Responsive.** Recolouring by `cell_type` takes 0.32 to 0.34 s. Zoom was not measured: the default tool is lasso, so the wheel event did not zoom.
- **Over the internet, from a hosted server.** The times are not comparable with local numbers. The first run was slower (17 s against 11 s), consistent with a cold server cache.

S1 for Explorer should therefore read "11.4M served and drawn (checked)". The 4.3M "documented" figure is the portal's submission note, not a measured limit.

### How to validate it yourself

1. Open https://cellxgene.cziscience.com/e/dcfd4feb-18a3-4b30-81d7-1b0c544a8ab3.cxg/ (11.44M cells). Time until the UMAP draws and check the cell count in the left panel. This is the one claim I did not see rendered.
2. On the same page, open Download (camera icon menu) and choose "Current view (.png)": a PNG of the embedding saves (plot export Y, Explorer).
3. Lasso a region, click "Subset to currently selected cells", then "Undo subset". The embedding is not recomputed (S4).
4. Select two groups with more than 1.5M cells in total and click compute DE: expect the "Too many cells selected" toast (hosted limit).
5. Copy the URL after colouring by a gene and open it in a new tab: the colouring is gone (shareable view state N).
6. Open http://127.0.0.1:8903 (Annotate on the 8,090-cell bone marrow h5ad, started by `$DEMO_ROOT/cellxgene/start.sh`). Create a category, label a lasso selection, check the CSV it writes (annotation editing Y). Confirm there is no PNG export and no spatial mode.
7. In the same Annotate session, open the embedding dropdown: only `obsm` keys starting with `X_` appear; nothing from `obsp`, `varp`, `varm` or layers.
8. Read `start.sh` for `--backed`: without it the server holds the whole matrix in memory (`ps -o rss` of the cellxgene process vs the h5ad size).
9. NAR 2025, PMC11701654, search "4.3 million": the S1 documented figure. bioRxiv 2021 abstract says only "millions of observations".
10. Run `curl -s https://api.cellxgene.cziscience.com/curation/v1/datasets | python3 -c 'import sys,json;d=json.load(sys.stdin);d.sort(key=lambda x:-x["cell_count"]);print([(x["cell_count"],x["explorer_url"]) for x in d[:3]])'` to re-rank Discover datasets by size (takes about 25 s).
11. Repeat the four rows of "Focus, feature colouring and selection" above: in Annotate (Mpo and Elane as x/y scatter, lasso the top arm) and in Explorer on Tabula Sapiens (side panel, MPO, lasso in each panel and read the counter). Expect Column 3 N and selection cross-filter Y. In a desktop browser, also confirm that Explorer's side panel dims after a lasso in the main panel.
