## Open questions for the author

These are decisions the evidence cannot make for you. Each one links to the tool files that hold the evidence.

### Q1. What does "focused cell/gene drives linked panels" mean?

Checked in the running apps (2026-10-03/04). The column now uses the strict definition: a focused cell or gene, through its stored pairwise row, re-drives every linked panel. AnnZarro is Y, Scanpy/Seurat P and every other tool N, iSEE included (its P becomes N). The evidence is in each tool's "Focus, feature colouring and selection" section. Two decisions are left for you: whether to adopt the strict definition and the new label, and whether the proposed "selection or filter restricts linked views" column should replace column 8 (see [_summary.md](_summary.md)).

### Q2. Should "P = only by writing code" apply to Scanpy/Seurat everywhere?

Under that rule, all-slots and shareable state move Y→P and every `?` becomes P, which makes the row nearly all P. The other reading is that, for a library, code is the interface, so most cells are Y. Pick one and state it in the legend. See [scanpy-seurat.md](scanpy-seurat.md).

### Q3. ShinyCell or ShinyCell2?

The row mixes the two programs. ShinyCell2 is the maintained successor, and it adds spatial coordinates and an image underlay, which would turn those two P marks into Y. ShinyCell (the 2021 paper) has neither. Either relabel the row "ShinyCell2" or keep P with a footnote. See [shinycell.md](shinycell.md).

### Q4. CELLxGENE: one row, two programs

Explorer (hosted, read-only, spatial, image, PNG export, lazy TileDB) and Annotate (pip, annotation, in-memory) differ on 7 of 16 columns. The row takes the best of both, which flatters it. Options are a footnote ("Explorer or Annotate") or two rows. See [cellxgene.md](cellxgene.md).

### Q5. Reported-scale column

Should it report the largest documented single dataset (my proposal; see the table in [_summary.md](_summary.md)) or the largest observed one? For CELLxGENE they differ: NAR 2025 documents 4.3M, and Discover serves 11.4M. I propose "4.3M documented; 11.4M served", or the larger number with its URL.

### Q6. Add any of the five unscored tools to Fig. 1c?

Single Cell Portal is the only other tool found that subsamples cells for display by default, which matters for the new Scale group. Kana is the only one that recomputes the analysis in the browser. Loupe has a desktop app with annotation editing and DE. All five rows are in `_summary.md`, ready if wanted.

### Q7. Things nobody could verify

- **Loupe lazy loading** (answered 2026-10-08): measured in the app on two files of the same 1,000,000 cells with 200 and 2,000 genes; memory after opening did not grow (median 1.273 and 1.272 GiB), so lazy is Y. How Loupe reads the file stays unknown (closed format), and only 1 million cells were tested. See loupe.md, Part D.
- **Cirrocumulus 1.3M**: the docs GIF does not name its dataset. The 10x 1.3M mouse brain set is inferred.
- **Rendering of the local demos**: each server answered and loaded the data, but no GUI was opened in a browser during the benchmark. See [_local_demos.md](_local_demos.md).
- **Single Cell Portal paper**: the bioRxiv full text returned 429, so the paper's own scale statements were not read.

### Q8. AnnZarro's own docs URL

Resolved. `https://annzarro.readthedocs.io` now answers 200 and redirects to `/en/latest/` (checked 2026-10-03). On 2 October it returned 404.

### Q9. Licences for the screenshots (needed before the evidence site goes public)

[`screens/SOURCES.yaml`](screens/SOURCES.yaml) lists every image with its tool, version, URL and dataset licence. It is generated by [`demos/make_sources.py`](demos/make_sources.py). Most entries say "to check" because they show the paper's own bone marrow demo data, and that data's release terms decide them. The rest are third-party datasets: SCP studies, SCope sessions, the ShinyCell2 showcase and one cells.ucsc.edu dataset. Datasets hosted on CELLxGENE Discover and 10x datasets are CC BY 4.0.
