### What it is

Loupe Browser is 10x Genomics' proprietary, closed-source desktop application (Windows, macOS) for "programming free interactive visualization" of Chromium single-cell and Visium spatial data ([What is Loupe Browser?](https://www.10xgenomics.com/support/software/loupe-browser/latest/getting-started/lb-what-is-loupe-browser)). It opens self-contained `.cloupe` files written by Cell Ranger, Space Ranger, 10x Cloud Analysis, or LoupeR. It is the default viewer that ships with the 10x pipeline, so it is the tool most 10x users meet first.

**Primary paper:** none. Loupe Browser has no peer-reviewed or preprint description. A Crossref bibliographic search for "Loupe Browser 10x Genomics" (checked 2026-10-03) returns only protocols.io walkthroughs (e.g. [10.17504/protocols.io.n92ld6qk8g5b/v1](https://doi.org/10.17504/protocols.io.n92ld6qk8g5b/v1), "Loupe Browser Access and Loading Data"), none by 10x. Cite it as software: "Loupe Browser v9.1.0, 10x Genomics, 2026".

**Version checked:** 9.1.0 (released April 7, 2026; native Apple Silicon build added June 22, 2026), per the [release notes](https://www.10xgenomics.com/support/software/loupe-browser/latest/release-notes/lb-release-notes). Download page: [Download Center](https://www.10xgenomics.com/support/software/loupe-browser/downloads) (Windows 705 MB, macOS Apple Silicon 767 MB, macOS Intel 783 MB). Docs: [support/software/loupe-browser](https://www.10xgenomics.com/support/software/loupe-browser). Everything checked 2026-10-03. The app was not downloaded and no account was created.

**Licence:** proprietary, free of charge, behind a click-through EULA ([End User Software License](https://www.10xgenomics.com/products/loupe-browser/downloads/eula); every "Download for ..." button goes through it). Key terms, by approximate section number in that page: a "limited, non-exclusive, non-transferable, non-sublicensable license" (s. 3.1); no decompiling or reverse engineering (s. 3.4); Licensee "shall use the Licensed Software solely with data generated using Products" (10x products), with only a de minimis allowance for non-10x data (s. 4.1); research use only, not diagnostic (s. 4.2). The EULA defines Licensed Software as provided "in conjunction with Buyer's purchase of a 10x Instrument" (s. 2.4). In plain terms: you may not legally load a Smart-seq2, Parse, or other non-10x dataset into Loupe, which matters for a comparison with general viewers.

**Input route, LoupeR.** [10xGenomics/loupeR](https://github.com/10xGenomics/loupeR) converts a Seurat object to `.cloupe`. Checked at commit [`b1cba07`](https://github.com/10xGenomics/loupeR/tree/b1cba07374f7326c6a69fddc2405e17157cb93de) (2026-04-24), release v1.1.5 (2026-02-04). It is **source-available, not open source**: GitHub reports `spdx_id: NOASSERTION`, and [LICENSE](https://github.com/10xGenomics/loupeR/blob/b1cba07374f7326c6a69fddc2405e17157cb93de/LICENSE#L1-L20) grants use "solely for your internal use", "only in connection with a 10x Genomics Product", and forbids redistribution (clause 3). The R code is a thin wrapper: it writes an HDF5 and calls a closed `louper` binary that `setup()` downloads after you accept the EULA ([README L98-L111](https://github.com/10xGenomics/loupeR/blob/b1cba07374f7326c6a69fddc2405e17157cb93de/README.md#L98-L111); [Loupe docs, LoupeR tutorial](https://www.10xgenomics.com/support/software/loupe-browser/latest/tutorials/introduction/lb-louper): "Please call `setup()` to agree to the EULA"). What it carries: the active counts matrix, factor columns of `meta.data`, and 2-D reductions only ([R/lib.R#L1-L5](https://github.com/10xGenomics/loupeR/blob/b1cba07374f7326c6a69fddc2405e17157cb93de/R/lib.R#L1-L5), [R/util.R#L151-L153](https://github.com/10xGenomics/loupeR/blob/b1cba07374f7326c6a69fddc2405e17157cb93de/R/util.R#L151-L153)). "Only single-cell gene expression datasets are supported" ([README L23](https://github.com/10xGenomics/loupeR/blob/b1cba07374f7326c6a69fddc2405e17157cb93de/README.md#L23)). Barcodes must match 10x patterns (14+ nt ACGT, Visium HD `s_008um_...`, Xenium, or `cellid_#########`) or the conversion fails ([R/validate.R#L96-L118](https://github.com/10xGenomics/loupeR/blob/b1cba07374f7326c6a69fddc2405e17157cb93de/R/validate.R#L96-L118)). There is no AnnData route from 10x; h5ad users go through Seurat first.

### Lazy reads: does Loupe load the expression matrix on opening? (checked in the running app, Part D)

**Checked in the app (2026-10-08, Loupe Browser 9.1.0).** Two `.cloupe` files with the same 1,000,000 Tahoe-100M cells (same cell lines, same UMAP) and different gene counts: `tahoe_first1000000_g200` (200 genes, 393,358,341 B) and `_g2000` (2,000 genes, 2,363,578,797 B, 6-fold), built with LoupeR (`benchmark/tool_ceiling/loupe_build.R`) from h5ads written by [lazy_inputs.py](../../benchmark/tool_ceiling/lazy_loupe/inputs/lazy_inputs.py). Each file was opened three times, each in a freshly started app, with memmon sampling the physical footprint of Loupe's process tree every 2 s ([protocol](../../benchmark/tool_ceiling/lazy_loupe/PROTOCOL.md), [records](../../benchmark/tool_ceiling/lazy_loupe/partD/), [readout](../../benchmark/tool_ceiling/lazy_loupe/partD/readout.txt)).

| GiB | g200 r1 | r2 | r3 | g2000 r1 | r2 | r3 |
|---|---|---|---|---|---|---|
| after opening | 1.134 | 1.273 | 1.281 | 1.095 | 1.272 | 1.280 |
| after MALAT1 coloring | 1.220 | 1.488 | 1.542 | 1.439 | 1.537 | 1.490 |
| peak of the run | 2.005 | 2.120 | 2.135 | 2.202 | 2.166 | 2.086 |

Median after opening 1.273 GiB (g200) and 1.272 GiB (g2000), difference -0.001 GiB against a file-size difference of 1.835 GiB. The rule fixed before the run (Y below 10% of the file-size difference, 0.183 GiB; N from 50%, 0.917 GiB) gives **Y**. The largest spread between repetitions of one file is 0.185 GiB, as large as the Y threshold, so the run shows "no growth with the file", not a precise zero. Coloring by MALAT1 raised the footprint by 0.09 to 0.34 GiB with no pattern by file; the peak while loading, 2.0 to 2.2 GiB, was not larger for the large file.

**What this does and does not establish.** At 1 million cells the expression matrix is not loaded whole when the file is opened. How Loupe reads the file (chunks, memory mapping, an index) is not documented and was not established; nothing above 1 million cells or at other gene counts was measured. The mark is Y under reading B.

**999,966 barcodes, not 1,000,000.** The legend under the MALAT1 coloring said "999966 barcodes found" in all six runs. Both h5ads have n_obs 1,000,000 with unique barcodes, the LoupeR build log reports 1,000,000 cells, and no cell lacks stored values; but exactly 34 cells have no MALAT1 count in both inputs ([barcode_check.txt](../../benchmark/tool_ceiling/lazy_loupe/inputs/barcode_check.txt)). 1,000,000 - 34 = 999,966, so the legend counts the cells with a nonzero value of the colored gene. Tested for this one gene only; the count under the cell_line_id coloring was not recorded.

**Deviations from the protocol** (from record.txt): markers, memmon and the record were run from Bash because computer use cannot type into Terminal, so marker times lag the visual moment by seconds; screenshots came from the desktop app's capture, not screencapture, and are redacted crops ([redact_lazy_shots.py](demos/loupe/redact_lazy_shots.py)); the file was opened by path entry (Cmd+Shift+G); g200 r1 waited 470 s for the lock; the g2000 r1 gene marker came about 43 s after the cell-line marker (focus went to Finder, steps redone); g200 r3 loaded slowly (10 to 18 s) and its trace has only 9 samples, so its "opened" value is the sample 14 s before the marker. `lazy_run.sh` and `lazy_watch.py`, the file-channel harness prepared for this test, were not used and are not in the repo.

### Tool-ceiling desktop session (v031): measured

Loupe Browser 9.1.0 was run in a Claude desktop session on 2026-10-05: benchmark/tool_ceiling/results.csv, rows loupe_default_*; channel files in `$DEMO_ROOT/loupe/session_v031/`.

- **Inputs:** each .cloupe was built by LoupeR 1.1.5 `create_loupe` (benchmark/tool_ceiling/loupe_build.R) from the shared tahoe_first<N>.h5ad (anndata 0.11.4, 5,000 genes). Barcodes were renamed `cellid_<9 digits>`. The clustering is cell_line_id and the projection is X_umap.
- **Every cell drawn** at 0.25M (1.15 GiB), 0.5M (1.48), 1M (2.21), 2M (3.18) and 5M (5.72 GiB, the Loupe process tree's phys_footprint). The cell count is the sum of the 50 cell_line_id cluster counts.
- **10M fails, twice:** cell_line_id drew all 10,000,000 cells. Opening Features (gene colouring, MALAT1) then left the window blank white, with no error dialog.
  - In attempt 2 a per-process sampler (logs/loupe_10M_r1_procs.jsonl) shows the Renderer helper growing to 4.03 GiB phys_footprint (4.32 GiB RSS). Its last sample is at 21:23:57, after which the process is gone. The other processes stayed small: loupeserver 2.58, GPU 2.22, main 0.05 GiB; the app tree peaked at 8.18 GiB.
  - This is consistent with a Chromium per-renderer V8 heap cap, but that is not established.
  - Either way it is far under the 16 GiB budget, and the input is not the limit.
- **Ceiling:** 5M.
- **20M input:** not built. After the 10M renderer failure it was moot for the ceiling, and a build of about 100 GB would have overlapped timed benchmark runs. The dgCMatrix limit on the LoupeR path (about 2.03e9 stored values at 20M, near 2^31) stays recorded as an untested input-path limit.
