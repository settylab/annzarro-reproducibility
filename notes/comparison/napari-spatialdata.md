### What it is

napari-spatialdata is the scverse plugin for the [napari](https://napari.org) desktop image viewer that opens SpatialData objects (images, labels, points, shapes and their AnnData tables) in one canvas. It adds three dock widgets: **View** (colour a layer by an obs column, a gene or an obsm column), **Scatter** (a pyqtgraph scatter plot with x, y and colour picked from obs, var or obsm, plus lasso/rectangle ROIs that become an obs column) and **Annotation** (draw shapes or points, give them a class and annotator, save them into the SpatialData object). It is a Python/Qt desktop GUI; there is no server and no browser client. Maintained by the SpatialData team (Palla, Marconato, Vierdag and co-authors).

**Primary paper** (Crossref-verified): Marconato L, Palla G, Yamauchi KA, Virshup I, Heidari E, Treis T, et al. (22 authors). SpatialData: an open and universal data framework for spatial omics. *Nature Methods* **22**, 58-62 (2025; online 20 March 2024). [doi:10.1038/s41592-024-02212-x](https://doi.org/10.1038/s41592-024-02212-x). The plugin is Fig. 1d and Extended Data Fig. 3 of that paper.

### Focus, feature colouring and selection (checked in the running app)

Checked 2026-10-03 in the local install (napari 0.9.2, napari-spatialdata 0.7.2, anndata 0.13.4, PyQt6) on the Visium demo. Its table carries obsp `spatial_kernel`, `spatial_distance`, `connectivities`, `distances` and varp `spearman_hvg`. The viewer was built with `Interactive(sdata, headless=True)`, and the View and Scatter widgets were driven through their own Qt methods (`var_widget._onAction`, list `itemClicked`, the Plot button) in [`demos/napari-spatialdata/focus_check.py`](demos/napari-spatialdata/focus_check.py). The window was saved with `viewer.screenshot(canvas_only=False)` and closed inside the script.

**Gene colouring is broken in this install.** Picking any gene in View > Vars raises `AttributeError: 'AnnData' object has no attribute '_get_X'` (`napari_spatialdata/_model.py` L139 calls the private `AnnData._get_X`, which anndata 0.13 no longer has). The screenshots below with a gene colour use a one-line shim, `AnnData._get_X = lambda self, layer=None: self.X if layer is None else self.layers[layer]`, applied only after the unpatched call had failed. A user with a current anndata hits the error; pinning anndata below 0.12 should avoid it, but I did not test that.

### How to validate it yourself

1. Run `$DEMO_ROOT/napari-spatialdata/start.sh` (bone marrow is not spatial, so it opens the Visium demo; colour the `cells` by a gene or `leiden` in the View dock). For the image underlay, download a SpatialData `.zarr` and pass it as the argument (e.g. the MIBI-TOF example from the [spatialdata datasets page](https://spatialdata.scverse.org/en/stable/tutorials/notebooks/datasets/README.html)). In the SpatialData dock pick a coordinate system, double-click an image then a labels element: image underlay sits under the labels (col 11 Y, col 7 Y).
2. Plugins > napari-spatialdata > View: confirm the lists are only Observations, Genes (var, with a layers dropdown) and obsm; no obsp/varp/varm/uns (cols 1, 2, 4). Cross-check [`_model.py#L40`](https://github.com/scverse/napari-spatialdata/blob/75b8c346bee64ad7428d753b62eb2f8dff64a0c2/src/napari_spatialdata/_model.py#L40).
3. Plugins > napari-spatialdata > Scatter: set x/y to `obsm spatial` 0/1, colour to a gene, Plot. Draw a lasso ROI, click Annotate, name it. Confirm the new column appears in View's Observations (col 9 in memory). Then click Save and check the terminal log for "Annotations only added in memory, please manually save to disk." and that the zarr on disk has not changed (`ls -lt <store>/tables/*/obs`) (col 9 P).
4. Draw a shape in a new Shapes layer, press Shift+E: same in-memory warning ([`_viewer.py#L177`](https://github.com/scverse/napari-spatialdata/blob/75b8c346bee64ad7428d753b62eb2f8dff64a0c2/src/napari_spatialdata/_viewer.py#L177)).
5. Click one cell in the canvas: only hover info appears; Scatter and View do not change (col 3 N).
6. File > "Save Screenshot..." writes a PNG (col 13 Y). Optional: right-click the Scatter plot and look for pyqtgraph "Export...".
7. Remote: `python -m napari_spatialdata view https://…/x.zarr` should fail on `assert p.exists()` ([`__main__.py#L47`](https://github.com/scverse/napari-spatialdata/blob/75b8c346bee64ad7428d753b62eb2f8dff64a0c2/src/napari_spatialdata/__main__.py#L47)); in Python `Interactive(sd.read_zarr("<https url>"))` should work (col 6 P).
8. Load a points element with more than 100k points: the log says "Subsampling points because the number of points exceeds the currently supported 100000" (S2).
9. Desktop app: download the napari 0.9.2 `.pkg` from [releases](https://github.com/napari/napari/releases/latest), Plugins > Install/Uninstall Plugins, search "napari-spatialdata", install, restart, open a `.zarr` (col 14; downgrade to P if it fails).
10.
