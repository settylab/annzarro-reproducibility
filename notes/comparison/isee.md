### What it is

iSEE (interactive SummarizedExperiment Explorer) is an R/Bioconductor package from Kevin Rue-Albrecht, Federico Marini, Charlotte Soneson and Aaron Lun. `iSEE(sce)` launches a Shiny app in which a server-side R process holds a `SummarizedExperiment`/`SingleCellExperiment`, renders each panel as a ggplot image, and passes selections between panels along a declared link graph. Every panel's output is produced by evaluating R command strings, which the app can hand back to the user as a script. A family of extension packages adds panels and deployment helpers (iSEEu, iSEEhex, iSEEde, iSEEpathways, iSEEindex, iSEEhub, iSEEfier, iSEEtree, miaDash).

**Primary paper.** Rue-Albrecht K, Marini F, Soneson C, Lun ATL (2018). iSEE: Interactive SummarizedExperiment Explorer. *F1000Research* 7:741. [doi:10.12688/f1000research.14966.1](https://doi.org/10.12688/f1000research.14966.1). Crossref-verified (issued 2018-06-14, vol 7, page 741). This is also the reference in `iSEE/inst/CITATION`.

[doi:10.1093/bioadv/vbaf107](https://doi.org/10.1093/bioadv/vbaf107). Crossref-verified (Crossref "issued" 2024-12-26, vol 5, article vbaf107). **Claim check: "iSEE exports the exact code behind a view".** Verified, with one caveat. Each panel's output is built by evaluating command strings (`.textEval` is `eval(parse(text=cmd))`, [R/utils_commands.R#L20-26](https://github.com/iSEE/iSEE/blob/f6c190304e95e35503a5cc9444c9e0607ddc58ab/R/utils_commands.R#L20-L26); for dot plots `list(plot=.textEval(plot_cmds, envir), commands=plot_cmds)`, [R/family_DotPlot.R#L1283](https://github.com/iSEE/iSEE/blob/f6c190304e95e35503a5cc9444c9e0607ddc58ab/R/family_DotPlot.R#L1283)), and those same strings are stored per panel ([R/utils_reactive.R#L39-43](https://github.com/iSEE/iSEE/blob/f6c190304e95e35503a5cc9444c9e0607ddc58ab/R/utils_reactive.R#L39-L43)). The menu item Export > "Extract the R code" ([R/iSEE-main.R#L203-211](https://github.com/iSEE/iSEE/blob/f6c190304e95e35503a5cc9444c9e0607ddc58ab/R/iSEE-main.R#L203-L211)) opens a "My code" editor filled by `.track_it_all` ([R/observers_general.R#L52-65](https://github.com/iSEE/iSEE/blob/f6c190304e95e35503a5cc9444c9e0607ddc58ab/R/observers_general.R#L52-L65), [R/utils_tracker.R#L18-50](https://github.com/iSEE/iSEE/blob/f6c190304e95e35503a5cc9444c9e0607ddc58ab/R/utils_tracker.R#L18-L50)), which concatenates the brush/lasso selection code and those evaluated plotting commands in link-graph order. So the exported code is the code that ran, not a reconstruction. Caveat: it starts from `se <- <your object>`; whatever produced the object before launch is not included. Safer wording for the paper: "iSEE exports the R code that generated each panel".

**Disagreements with current marks**

1. Focused cell/gene drives linked panels: **P -> N under the strict definition** (checked in the running app; see the Focus section). Superseded reasoning, valid only under the old loose definition, which proposed P -> Y: iSEE's "single selection" does exactly what the column defines (one gene or sample chosen in a table or plot recolours or re-axes other panels); `vignettes/links.Rmd` L225-262. Everything else unchanged. Borderline but kept: remote stores N (iSEEindex downloads whole RDS from HTTPS/S3), spatial N (coordinates only via a code-side copy into reducedDims).

**Marks**

- `Column 3 (strict): N` (was P in `fig_comparison.py`; this audit had proposed Y). iSEE's "single selection" carries a gene or cell *identity*: a gene becomes feature colouring, and a cell becomes a red dot. No shipped panel turns the focused cell into its row of `colPairs` or any other relation, and a precomputed colData row does not follow the focus. The earlier Y rested on this (a2)-type mechanism, which the strict column excludes. A user could write a custom `Panel` subclass that reads `colPair(se)[i, ]` for the transmitted sample. That would justify P, but no such panel exists in iSEE or its nine extensions, and I did not write one.
- `Proposed column "selection cross-filters linked views": Y`. A brush in one plot highlights the same cells in another, and with "Restrict" filters them, entirely in the GUI.

**Could not do:** nothing failed. The panel layout was preset in code to save lock time rather than clicked together. The "Restrict to selected samples" label in the older checklist step 5 now reads "Restrict to selected columns" in 2.18.

### How to validate it yourself

1. Open https://isee.github.io/iSEE/articles/bigdata.html. Confirm the printed `dim: 32738 68579` (S1), the "Downsampling points" section (S2) and "retrieved on demand" HDF5 text (S3).
2. Start the local demo: `$DEMO_ROOT/isee/start.sh`, open http://127.0.0.1:8902 (bone marrow, 8,090 cells, has a colPair). In Reduced dimension plot 1, open "Visual parameters" > "Color by": confirm only None / Column data / Feature name / Sample name / Column selection (no pairwise option) for columns 1-2.
3. Same panel, "Visual parameters" > "Point" (or "Size" box): tick "Downsample points for speed", note the "Sampling resolution" field; confirm the plot thins (S2, S4).
4. In Row data table 1 click a gene; in Reduced dimension plot 1 set Color by "Feature name" with "Receive feature selection from" = Row data table 1; confirm the colour changes to that gene (column 3).
5. In Column data table 1 type a filter in the search box; in Reduced dimension plot 1 under "Selection parameters" choose Column data table 1 as source and tick "Restrict to selected samples"; confirm the plot shows only the filtered cells (column 8, S4).
6. Top bar Export (download icon) > "Extract the R code": confirm the code starts `se <- ...` and includes the ggplot calls for each panel. Then "Download panel output" (PDF/CSV zip, column 13) and "Display panel settings" > "Download RDS" (column 12).
7. Open https://kevinrue.shinyapps.io/isee-shiny-contest/ (wait for the worker, about 10-30 s): the only documented live instance. Optionally retry the five README URLs (README.md L114-120) to confirm 503/timeout.
8. Open https://github.com/iSEE/iSEEu/blob/2f5ca87331d85898802d8e0517087c478fb5a003/R/DynamicMarkerTable.R#L303-L309 and decide whether an extension panel added in code counts as P for on-the-fly DE.
9. Run `grep -rn -i "colPair\|rowPair\|imgData" --include='*.R' $DEMO_ROOT/isee` and confirm zero hits across iSEE and its nine extensions (columns 1, 2, 7, 11).
10. Verify the DOI: `curl -s https://api.crossref.org/works/10.12688/f1000research.14966.1 | head -c 600`.
11. Focus vs selection: start the preset layout (`Rscript notes/comparison/demos/isee/focus_app.R`, or build it by hand) and repeat the four rows of "Focus, feature colouring and selection" above: click `Mpo` in Row data table 1, click cell `TCAATTCAGTGAGGCT` in Column data table 1, brush plot 1 and tick Restrict in plot 2.
