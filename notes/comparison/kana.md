### What it is

Kana is a single-cell analysis web application that runs the whole analysis inside the browser. It was written by Aaron Lun and Jayaram Kancherla (Genentech; the licence holder is Genentech, Inc.). The C++ libraries (libscran, tatami, igraph, HDF5) are compiled to WebAssembly as [scran.js](https://github.com/kanaverse/scran.js), wrapped by the workflow package [bakana](https://github.com/kanaverse/bakana), and Kana is the React front end. From a count matrix it runs QC, normalisation, HVG selection, PCA, SNN or k-means clustering, t-SNE/UMAP, marker detection, gene set enrichment and SingleR-style labelling. An "explore-only" mode instead opens pre-analysed H5AD or SingleCellExperiment files without recomputing. It is not in the Fig. 1c matrix yet; COMPARISON_NOTES.md L13 lists it under "tools dropped".

### How to validate it yourself

1. Open https://www.kanaverse.org/kana/ (no login). Pick "New Analysis", tab "ExperimentHub", dataset "Mouse brain (Zeisel et al., 2015)", and click Analyze. Confirm the QC → PCA → clustering → t-SNE/UMAP → markers sequence runs in your browser (DevTools Network shows only gypsum downloads through `cors-proxy.aaron-lun.workers.dev`). That settles static site (Y) and on-the-fly DE (Y).
2. In the embedding, switch on lasso selection, draw a selection, and check that a "Selection 1" entry appears with markers computed for it. Note there is no rename field (annotation editing P).
3. Click the droplet icon next to a marker gene and see the embedding recolour (decides focused cell/gene N vs P).
4. Click "Save as SVG" above the embedding; a `.svg` downloads (plot export Y).
5. Use Export to download a `.kana` file. Reload the page, use "Load analysis" with that file, and confirm the analysis and selections come back but the chosen colouring/gene does not (shareable view state P).
6. In New Analysis, open the H5AD tab and look for an option to give a URL. There is none; the only remote source is the 8-item ExperimentHub list ([K/src/workers/scran.worker.js#L269-L278](https://github.com/kanaverse/kana/blob/ecb0360c5e00200ed9cee2d73d45725e93d53a39/src/workers/scran.worker.js#L269-L278)).
7. Heap limit of the live build: `curl -sL https://www.kanaverse.org/kana/asset-manifest.json | grep wasm`, download that `.wasm`, and parse the import section. A Python snippet that walks section id 2 printed `mem import flags 0x3 min pages 256 max pages 65536` on 2026-10-03, i.e. shared, 32-bit, 4 GiB max. Flags `0x7` would mean memory64.
8. Read the JOSS PDF Table 1 (largest row: Zilionis, 173,954 cells) and [KP/main.tex#L297-L321](https://github.com/kanaverse/kana-paper/blob/220a3d64fa7f721dc8d14b98afb16cf2672a1fee/main.tex#L297-L321) (2,481 MB heap; 4 GB hard limit).
9. Open [B/src/readers/h5ad.js#L38-L50](https://github.com/kanaverse/bakana/blob/299c4da177d16451e92a32f31ae2db1eb31db617/src/readers/h5ad.js#L38-L50) and [#L617-L623](https://github.com/kanaverse/bakana/blob/299c4da177d16451e92a32f31ae2db1eb31db617/src/readers/h5ad.js#L617-L623). Only X/layers and obsm are opened, plus obs/var elsewhere, so the obsp/varp/varm columns are N.
10. Optional: load an H5AD that has `obsm['spatial']` in "Explore" mode and check whether "spatial" is offered as an embedding (settles the spatial P).
11. Like-for-like: in Kana, choose New Analysis, then H5AD, and pick `$DEMO_ROOT/_data/bm_demo.h5ad` (the shared 8,090-cell bone marrow demo, 356 MB, with `layers/counts`). Kana reads it in the browser and uploads nothing. Check that the stored UMAP and the three obsp matrices are not offered, and that the analysis is recomputed.
12. Focus and selection: follow "Focus, feature colouring and selection (checked in the running app)" above in Explore mode with `bm_demo.h5ad` (window at least 1800 px wide): Mpo droplet recolours only the main embedding, a lasso highlights only there, and no obsp key is offered. Decides Column 3 (N) and the selection column (P).
