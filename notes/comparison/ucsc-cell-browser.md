### What it is

The UCSC Cell Browser is made by the UCSC Genomics Institute (Genome Browser group, Maximilian Haeussler's team). A Python builder (`cbBuild`, or `cbImportScanpy` for h5ad) converts a matrix, metadata and embeddings into a directory of static files: JSON configuration, one gzip'ed binary vector per gene inside `exprMatrix.bin` with a JSON offset index, per-field metadata files and binary coordinate files. A JavaScript viewer reads these files directly from any web server. The public portal at cells.ucsc.edu is one deployment of the same code.

**Primary paper.** Speir ML, Bhaduri A, Markov NS, Moreno P, Nowakowski TJ, Papatheodorou I, et al. (2021). UCSC Cell Browser: visualize your single-cell data. *Bioinformatics* 37(23):4578-4580. [doi:10.1093/bioinformatics/btab503](https://doi.org/10.1093/bioinformatics/btab503). Crossref-verified 2026-10-03 (title, journal, volume 37, issue 23, pages 4578-4580, issued 2021-07-09).

**Repository.** [ucscGenomeBrowser/cellBrowser](https://github.com/ucscGenomeBrowser/cellBrowser), commit `a11af81` (2026-09-29), shallow clone at `$DEMO_ROOT/ucsc-cell-browser/src`, checked 2026-10-03. Permalinks below use `https://github.com/ucscGenomeBrowser/cellBrowser/blob/a11af81299cc13dfe1ab7b063f03205b75b13913/<path>`; `JS/` abbreviates `src/cbPyLib/cellbrowser/cbWeb/js/`.

**Docs.** [cellbrowser.readthedocs.io](https://cellbrowser.readthedocs.io/en/master/) (200). Some newer pages (for example `docs/ui/diffexp.rst`) exist only in the repository's `docs/` at this commit, so line references below point there.

**Licence.** GPL-3.0 (`LICENSE` file at the commit; GitHub API `spdx_id: GPL-3.0`).

**Could not do / caveats:** (1) Typing `Mpo` in the selectize gene box from Playwright picked `Tmpo` (the dropdown options were not readable in time), so the gene screenshots load the gene with the URL parameter `&gene=Mpo`; a person typing and choosing `Mpo` gets the same view. (2) In headless Chromium the right pane of the split draws only part of the cells (a canvas offset; visible in screenshots 02 and 03). The selection reached the right pane only after a redraw (clicking the 100% zoom button); I did not check whether a desktop browser redraws without that. (3) Hover-to-update of the metadata panel did not fire from synthetic mouse moves; a click was used instead. (4) Both panes showed the same layout (UMAP); I did not switch the right pane to another embedding.

### Scale check: the 21.8M-cell PanSci dataset in a browser

I checked this on 2026-10-04 with three runs in headless Chromium. Each run used a fresh browser. The question was whether the largest single dataset on the portal really draws every cell.

**Dataset.** [PanSci Organismal Aging, "All"](https://cells.ucsc.edu/?ds=mouse-pansci+all) has 21,786,931 cells (`sampleCount` in [`dataset.json`](https://cells.ucsc.edu/mouse-pansci/all/dataset.json)). The `?ds=collection+subdataset` URL form is the documented one ([`docs/ui/examples.rst` L15](https://github.com/ucscGenomeBrowser/cellBrowser/blob/a11af81/docs/ui/examples.rst#L15)). Walking every collection's `dataset.json` (314 collections, 1,570 leaf datasets; coordinator's crawl) sums to 166M cells. That is where the portal's "160 million cells" comes from, and it counts overlapping datasets: for example, `mouse-pansci/all` and its per-organ parts. The next largest single datasets are whole-brain-perturb/combined (6.35M) and fetal-gene-atlas/all (4.06M).

**Method.** [`demos/scale_probe/probe_web.py`](demos/scale_probe/probe_web.py) used Playwright 1.63 with bundled Chromium 153 in new headless mode and `--enable-precise-memory-info`, the same flags as `benchmark/scale/ceiling/ceiling.py`. WebGL was ANGLE Metal on an Apple M3 Max.
- An init script wraps every WebGL draw call: `drawArrays`, `drawElements` and the instanced variants, on both WebGL contexts. It records the largest point count of any single call and when that call happened. These counts are what the GPU was asked to draw, not what a UI label says.
- Network bytes come from Playwright's per-request sizes.
- The JS heap is `performance.memory.usedJSHeapSize`, read 3 s after the first full draw. The renderer and GPU process RSS are peaks sampled every 0.2 s.
- Responsiveness is the time from an action to the next draw of at least 99% of all points, for three actions: a wheel zoom, recolouring by the "Organ name" annotation, and recolouring by the gene Malat1. The PanSci build indexes genes by Ensembl id only, so Malat1 is `ENSMUSG00000092341`.
- The runs did not hold the bench lock. Each run waited until no timed benchmark (`memmon.py`) was running. The UTC windows are in [`demos/scale_probe/windows.log`](demos/scale_probe/windows.log) and in `benchmark/scale/NOTES.md`. Raw rows: [`demos/scale_probe/results.jsonl`](demos/scale_probe/results.jsonl).

| Run (UTC start) | Points in one draw call | First full render | Zoom redraw | Recolour by annotation | Recolour by gene | JS heap | Renderer RSS peak | GPU RSS peak | Network |
|---|---|---|---|---|---|---|---|---|---|
| 08:06:47 | 21,786,931 | 7.26 s | 32 ms | 0.48 s | 4.25 s | 574 MB | 1.72 GB | 0.99 GB | 204 MB |

Times count from navigation start. The single-rep smoke tests on 2026-10-03 agreed: 7.35 to 7.57 s, the same point count, and a JS heap of 1.1 GB. The heap reading varies between about 0.57 and 1.14 GB depending on when garbage collection last ran, so read it as a range.

**Findings**
- **Every cell is drawn.** One `drawArrays(POINTS)` call draws all 21,786,931 cells, with no sampling. The status bar says "21786931 cells loaded", and the gene violin says "n=21,786,931" ([s04](screens/ucsc-cell-browser/s04_scale_recolour_gene.jpg)).
- **What crosses the network.** The coordinates are one file of 174,295,448 bytes, exactly 8 bytes per cell (Float32 x and y). In transfer it was 166 MB, after compression. One annotation field was 8.4 MB, the gene index 0.7 MB, and one gene's values (Malat1) 27.6 MB, fetched by an HTTP Range request.
- **It stays responsive.** A zoom redraws all points in 28 to 40 ms. Recolouring by an annotation takes 0.48 s. Recolouring by a gene takes about 4.3 s, most of it downloading that gene's 27.6 MB.
- **Client cost.** JS heap 0.57 to 1.14 GB and renderer RSS 1.7 to 2.4 GB for 21.8M points, roughly 26 to 52 bytes of heap per point. That is far lighter per point than AnnZarro's large-plot mode.
- **The times are not comparable with the paper's local numbers.** The data come over the internet: `curl` fetched the coordinate file at 68.5 MB/s (2.5 s) on 2026-10-04. Nothing here measures a local build or a ceiling. ceiling-benchmarker owns the like-for-like ladder for the UCSC Cell Browser (`cbImportScanpy`, `cbBuild` and then the viewer, up to 95.6M cells), and that is the number for the figure.

### How to validate it yourself

1. Open [cells.ucsc.edu/mouse-pansci/all/dataset.json](https://cells.ucsc.edu/mouse-pansci/all/dataset.json) and search for `sampleCount`: it should read `21786931`.
2. Open [cells.ucsc.edu/?ds=mouse-pansci+all](https://cells.ucsc.edu/?ds=mouse-pansci+all) in Chrome on a machine not running a benchmark. Expect a 174 MB coordinate download. Check that the status bar shows about 21.8M cells and that the UMAP renders. Note load time and whether the tab stays responsive (not tested by me).
3. In DevTools > Network on that page, click a gene in the gene list. Confirm a request to `exprMatrix.bin` with status 206 and a `Range` header, a few hundred kB to a few MB rather than 27.8 GB.
4. Open [`JS/cellBrowser.js` L8111-8113](https://github.com/ucscGenomeBrowser/cellBrowser/blob/a11af81299cc13dfe1ab7b063f03205b75b13913/src/cbPyLib/cellbrowser/cbWeb/js/cellBrowser.js#L8111): WebGL is chosen when `sampleCount > 200000`. Then [`maxPlot.js` L2228](https://github.com/ucscGenomeBrowser/cellBrowser/blob/a11af81299cc13dfe1ab7b063f03205b75b13913/src/cbPyLib/cellbrowser/cbWeb/js/maxPlot.js#L2228): `drawArrays(POINTS, 0, count)` draws every cell.
5. On [?ds=adultPancreas](https://cells.ucsc.edu/?ds=adultPancreas), switch to select mode, drag a box, click "Only show selected", then "Show all" (S4).
6. Same dataset: File > "Download vector image (SVG)" (plot export), and copy the URL after colouring by a gene, paste it in a new tab, confirm the view returns (shareable state).
7. Same dataset: Edit > Find Cells, pick a cluster; matched cells highlight, others dim (table filters = P, no table).
8. In the clone, run `grep -rn "obsp\|varp" $DEMO_ROOT/ucsc-cell-browser/src/src/cbPyLib/cellbrowser/*.py`: no output (relationship columns N).
9. Optional: rerun `python3 ucsc_crawl.py` from the scratchpad (needs `ucsc_root.json` from `https://cells.ucsc.edu/dataset.json`) to reproduce the top-15 dataset sizes.
10. Run `$DEMO_ROOT/ucsc-cell-browser/start.sh`, open http://127.0.0.1:8906/?ds=bm_demo and repeat steps 3, 5 and 6 offline.
11. Repeat the four rows of "Focus, feature colouring and selection" above on the local demo (click one cell, `&gene=Mpo` plus split screen, lasso in the left pane); expect Column 3 N and selection cross-filter Y.
